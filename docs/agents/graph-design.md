# 依頼のグラフの設計

## 目的

この文書は、ダッシュボードのグラフを作り直すときの正本である。
目標は、誰が誰に何を頼み、いま誰が動いているかを一目で示すことだ。
値は `design-system.md` だけから取り、足す値は先にそちらへ書く。

## 優れた例から学ぶこと

| 例 | 学ぶこと | 取り入れ方 |
| --- | --- | --- |
| LangSmith の trace | 木の行と時間の棒を同じ行に並べる。入れ子で親子が、棒で長さと並行が分かる。 | 全画面を、左が木で右が時間の棒の滝の図にする。 |
| Temporal の Timeline | 予定と開始と完了を 1 つの群にまとめ、1 本の棒にする。完了は緑、失敗は赤で示す。 | 同じ子への往復を 1 行にまとめ、棒を区切りで分ける。 |
| Airflow の Grid と Gantt | 状態を色の四角で並べ、別の画面で時間の並びを見せる。色だけでは名前が読めない苦情がある。 | 状態は色と語の両方で出す。題は常に 1 行で読める幅を取る。 |
| Linear と Vercel | 1 行の密な一覧と、右端の経過の数字で進みを示す。動く段にだけ最新の 1 行を添える。 | 実行中の行にだけ、いまの作業を 2 行目に出す。 |

## 図の型

両方の幅で、同じ行の並びを使う。行は根を頂点とする依頼の木である。
狭い幅は木の行だけにし、全画面は木の行に時間の棒を足す。

| 場所 | 型 | 理由 |
| --- | --- | --- |
| 右のパネル | 字下げの木 | 420px では横の層も時間軸も題を潰す。縦の 1 行なら題を 1 行で読める。 |
| 全画面 | 木と時間の滝 | 誰が誰に頼んだかを木で、いつ何が並んで動いたかを棒で示す。 |

役ごとの列は採らない。親子の線が列をまたぎ、誰が頼んだかが切れる。
ノードを自由に置く図もやめる。数百件では線が交わって読めなくなる。

## ノード

### 行の形

ノードは全て 1 行 32px の行にする。カードの枠と角と影はやめる。
行の地は `--bg-0` にし、指を置いたら `--bg-2`、選んだら `--bg-3` にする。

| 位置 | 中身 | 決まり |
| --- | --- | --- |
| 1 | 字下げと線 | 1 段 16px で字下げし、親からの線を引く。 |
| 2 | 状態の点 | 16px の枠に 6px の点を置く。色は `--state-*` に従う。 |
| 3 | 役の印 | 16px の印を `--fg-2` で置く。形は下の表に従う。 |
| 4 | 題 | 頼んだ題を `--type-ui` で 1 行に切る。全文は `title` に入れる。 |
| 5 | 役と相手 | 「Work · Codex」の形で `--type-meta` の `--fg-3` にする。 |
| 6 | 右端の語 | 実行中は経過、あなたの番は状態の語、それ以外は終えた時刻にする。 |

### 役の印

役は印の形と語で示し、色は使わない。色は状態だけに使うと決めているからだ。
役と状態の両方を色にすると、緑の作業と緑の実行中が区別できなくなる。

| 役 | 印 | 語 | 入る種類 |
| --- | --- | --- | --- |
| 根 | `message` | Main | 利用者と話す根のセッション |
| 調査 | `search` | Research | Explore、claude-code-guide |
| 計画 | 新しい `plan` | Plan | Plan、タスクグラフのまとまり |
| 作業 | `tool` | Work | general-purpose、Codex の implement、直接の codex exec |
| レビュー | `check` | Review | reviewer、Codex の review |
| 文書 | `file` | Docs | doc-light、doc-heavy |
| その他 | `dot` | Other | 上のどれにも当たらないもの |

- 役の分け方は、別の作業者が作る分類の関数をそのまま使う
- 相手は Claude ならモデルの短い名、Codex なら「Codex」と書く。提供元の色の印は詳細の面だけに残す

### 状態

状態は点の色と、右端の語で示す。点の色は `design-system.md` の 6 色である。

| 状態 | 点 | 右端の語 | 題の色 |
| --- | --- | --- | --- |
| 実行中 | 脈打つ点 | 経過を「4m」の形で書く | `--fg-1` |
| 承認待ち | 塗った点 | 「Approval」をその色で書く | `--fg-1` |
| 返答待ち | 塗った点 | 「Your turn」をその色で書く | `--fg-1` |
| 失敗 | 塗った点 | 「Failed」をその色で書く | `--fg-1` |
| 完了 | 塗った点 | 終えた時刻を `--fg-3` で書く | `--fg-2` |
| 待機 | 中を抜いた輪 | 終えた時刻を `--fg-3` で書く | `--fg-2` |

根の子孫が動いていれば、根の右端に「2 running below」と書く。

### 動いているものの目立たせ方

目立たせる手段は 3 つ重ねる。どれも新しい色を足さない。

1. 実行中の行だけ 2 行にし、2 行目にいまの作業を `--type-meta` の `--fg-2` で出す
2. 根から実行中の行までの親の線を、`--state-running` の 1px にする
3. 実行中とあなたの番の行は、畳みの規則から外して必ず見せる

2 行目は「Editing roles.ts」の形で最後のツールと対象を書き、行は 52px にする。

### 頼んだ題

題は、依頼の `description` を第一にし、無ければ会話の名前を使う。
タスクグラフの依頼は、題の前に「T3」の形の番号を `--fg-3` で添える。
まとまりの行はグラフの名前を題にする。時刻が無ければ右端を空ける。

## 線

線は全て 1px の `--line` にし、矢じりは付けない。字下げが向きを示すからだ。

| 関係 | 描き方 |
| --- | --- |
| 頼んだ向き | 親の点の真下から下りて、子の点の左で止める。親から子へ、上から下へ流れる。 |
| 往復 | 指示し直しは新しい行にせず、右端に「×3」を `--fg-3` で書く。全画面では棒を往復ごとに区切る。 |
| レビュー | レビューの行は、対象の作業の子に置く。対象が分からなければ親の子に置き「推定」と書く。 |
| レビューの結果 | 右端に「Pass」か「Changes」と書く。差し戻しの後の作業は、作業の行の往復に数える。 |

## 一目で分かる要約

図の上に 32px の要約の行を 1 本だけ置く。地は `--bg-0`、下に `--border` を引く。

| 部分 | 中身 |
| --- | --- |
| 左 | 「2 running · 1 needs you」を点と語で示す。0 の項目は出さない。 |
| 右 | 役ごとの件数を「Work 12 · Docs 3 · Review 2」の形で並べる。0 の役は出さない。 |

- 件数は、この根の依頼の全てを数える。畳んだ行も数に入れる
- 役の語は押せる。押すとその役の行と、その祖先の行だけを残す
- 絞った役の語は `--fg-1` にし、ほかを `--fg-3` にする。もう一度押すと戻す
- 右のパネルで幅が足りなければ、末尾を「+2」にまとめる

## 畳み方

依頼は数百件あるので、既定では今の作業に関わる行だけを出す。

| 群 | 既定 | 決まり |
| --- | --- | --- |
| 実行中とあなたの番 | 開く | 常に出す。祖先の行も出す。 |
| 24 時間以内の失敗 | 開く | 常に出す。 |
| 2 時間以内の完了 | 開く | 親ごとに新しい 5 件まで出す。 |
| 今日のほかの完了 | 畳む | 親ごとに 1 行の「Today 9」にまとめる。 |
| それより前 | 畳む | 親ごとに 1 行の「Earlier 38」にまとめる。 |

- 畳んだ行には、役ごとの件数を「Work 22 · Docs 9」の形で添える
- 畳んだ行を押すと、その場で 20 件ずつ開く。末尾に「Show 20 more」を置く
- 開いた群は URL の `expanded` に残し、再読み込みでも保つ
- 選んだ行の祖先の群は、自動で開く

## 選んだときの動き

| 操作 | 右のパネル | 全画面 |
| --- | --- | --- |
| 押す | 行を選び、真ん中にその子の会話を開く | 行を選び、右に詳細の面を開く |
| 二度押す | 押すと同じ | 真ん中の会話の画面へ移る |
| 上と下の矢印 | 行を移る | 行を移る |
| 右と左の矢印 | 群を開く、閉じる | 群を開く、閉じる |

- 選んだ行の祖先の線を `--fg-2` にする。実行中の線の色はそのまま残す
- 詳細の面は幅 360px の浮いた面にし、`--radius-2` と `--shadow` を付ける
- 詳細には依頼の全文と報告の 1 行目、相手、経過、往復の数を出す
- 承認待ちの行は、直下に 28px の承認の行を足す。中身は `--type-mono` と小さいボタンにする
- 会話から依頼のカードを押したら、その行を選んで見える位置まで送る

## 全画面の時間軸

- 棒は高さ 12px、角 `--radius-1` で、行の縦の真ん中に置く
- 棒の色は状態の色にし、完了と待機は透明度 0.5 で塗る
- 実行中の棒は「Now」の縦線まで伸ばし、10 秒ごとに伸ばす
- 「Now」の縦線は 1px の `--fg-3` にし、上端に語を添える
- 30 分を超える空きは、幅 16px の「≈」の切れ目に詰める
- 上の目盛りは `--type-meta` の `--fg-3` で、時刻だけを書く
- 範囲は 1h、6h、24h、All の区切りボタンで選ぶ。既定は 6h にする
- ドラッグの移動とホイールの拡大は捨て、縦のスクロールだけにする
- 子が始まった時刻に、親の棒から子の棒へ 1px の縦線を引く

棒の高さ 12px は、帯ではなくデータの印として `design-system.md` に足す。

## 実装者への手順

各段の受け入れは、次の 4 つを全て満たすことにする。

- `npx --yes pnpm@10 --filter @agent-graph/dashboard test:app` が通る
- `npx --yes pnpm@10 --filter @agent-graph/dashboard build:app` と `npx --yes pnpm@10 typecheck` が通る
- 撮り直した `panel.png` と `full.png` を、今の画像と並べて見る
- `graph.css` に `grep -nE '(^|[^0-9])1[01]px|1\.5px|dashed|#[0-9a-fA-F]{3,6}'` が 0 件になる

| 段 | 中身 | 触るファイル |
| --- | --- | --- |
| 1 行の模型 | 木を行の並びに変える関数を作る。役の分類、畳み、往復、要約の数、実行中の道を返す。 | 新しい `pages/graph/rows.ts`、`layout.ts` の畳みを移して座標の計算を消す、`test/graph-rows.test.ts`、`test/graph-projection.test.tsx` |
| 2 右のパネル | 要約の行と字下げの木を作る。承認の行と矢印の操作を移す。 | 新しい `pages/graph/GraphOutline.tsx`、`GraphPage.tsx`、`graph.css`、`components/Icon.tsx` の `plan`、`lib/i18n.ts` |
| 3 全画面 | 木の欄と時間の欄と詳細の面を作る。ドラッグと拡大の操作を消す。 | 新しい `pages/graph/GraphTimeline.tsx` と `GraphDetail.tsx`、`GraphPage.tsx`、`graph.css`、`docs/agents/design-system.md` の棒の値 |

- 段 1 は、役の分類の関数が入った後に始める。無ければ `other` に倒す仮の関数を置く
- `WorkspacePanel.tsx` と `App.tsx` の呼び出しの形は変えない
- 段 3 の最後に、`layout.ts` の `calculateLayout` と `curvePath` が残っていないことを確かめる

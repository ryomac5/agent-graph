### T5 止まった子

- 原因は `70b1726` の `buffered.batch(() => claudeChildren.observe(...))` である。
- これが書き込みの錠を毎周期取り、読み手の refresh が busy_timeout 1 秒で locked になった。
- locked は握りつぶされ、resync が届かず、送信が落ちた。反映前の本番では RSS が 1.9 GB で、`Session scan persistence failed: database is locked` が 66 回出ていた。
- `b4f28d7` で外し、`a17700d` で入れ直した。ps と transcript の読み取りは取引の外に出し、追記ゼロなら取引を開かない。
- 本番の DB で、Agent ツールの子 7 行は idle であり、running ではなかった。T5 の効果の証拠にならない。
- 画面で Running に見えた件は、実際には下の節の Codex の委譲 11 行だった。
- 親の会話が落ちた子の解消は、本番では確かめていない。親が落ちる状況を作らないと確かめられず、隔離環境の試験でだけ確かめた。

### T6 端末の持ち主を runner へ

- 隔離環境で、偽 claude の会話を api だけの再起動の前後で 2 つの検査にかけ、両方 PASS した。
  - `restart-check.mjs` は WebSocket で、同じ pid と同じ terminalId のまま送信できた。

- runner の再起動で端末は切れる。素のシェルも含め範囲外である。
- 本物の claude を使ったブラウザ経由の実操作は、使用量の都合で流していない。

## 学んだこと

- 関門の locked 検知は、stderr の文字列を数えるだけである。握りつぶされた例外は捕まえない。
- 送信の合否と画面の更新を見ること。
- 本番へ反映する前後に、prod-gate の送信を流す。試験が通っても、本番の経路は覆わない。
- T7-4 は HTTP 経路の試験だけで、outbox 経路の穴を見逃した。
- 本番に出す前後と完了の報告の前に、実際の画面を撮って画像を読む。DOM の Running の行と「Unknown time」の有無、Reconnecting を見る。
- 子を `kill`、`agr close`、`TaskStop` で止めた後は、画面から取り残しが消えたかを撮って確かめる。
- Codex を起動した後は `agc wait` を張って、完了の取りこぼしを防ぐ。
- 「未確認」「未調査」で報告を終えない。確かめる手段があれば確かめる。
- 閉じたグラフは再開できない。終わったグラフへの追加は、別の識別子の新しいグラフにする。
- 本番は main の作業ツリーから動く。起動し直しの直前に `git status --short` を確かめ、未コミットの編集があれば待つ。

## 委譲の進め方

- 実装は Codex に任せる。Codex の環境は socket の listen と ps を拒否するので、socket の試験、e2e、本番の写しの確認は Claude の子に流させる。
- レビューは、実装と別の系統に任せる。
- 確かめの会話は、利用者のプロジェクトの外で起こす。利用者のプロジェクトで起こすと、サイドバーが試しの会話で埋まる。
- 起動し直しを頼むのは、変えたパッケージだけにする。runner を変えていないのに、runner の起動し直しを頼まない。

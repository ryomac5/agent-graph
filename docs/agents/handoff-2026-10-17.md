## T の結果

### T1 本番規模の関門

- 場所は `scripts/e2e/prod-gate.mjs` である。
- 本番 DB の `VACUUM INTO` の写しの上で、api と runner を別 port で立て、偽 claude で送信まで通す。
- 判定は送信、Reconnecting、RSS、api の生存、locked である。RSS の上限は 1600 MiB で、傾きも見る。locked の許容は 10 である。
- `E2E_CODE_ROOT` で試す版を指定する。
- 読み直しは約 8〜14 秒で、本番の約 7 分は再現しなかった。newstate 固有の負荷だった可能性があるが、推測である。
- 会話の cwd が `$TMPDIR` 配下だと、製品が登録を拒む。cwd は `scripts/e2e/.runs/` に置く。

### T2 newstate

- 捨てる。
- locked を握りつぶす構造が 5 か所ある。`projection-feed.ts:390`、`current-state.ts:306`、`current-state.ts:800`、`observation-worker.ts:49`、`service/index.ts:168` である。

- locked は、握りつぶしに stderr の出力が無く、関門では見えなかった。
- 判定の関数は、本番の写しで正しい。場所は `packages/core/src/state/` である。

### T5 止まった子

- 原因は `70b1726` の `buffered.batch(() => claudeChildren.observe(...))` である。
- これが書き込みの錠を毎周期取り、読み手の refresh が busy_timeout 1 秒で locked になった。
- locked は握りつぶされ、resync が届かず、送信が落ちた。
- 反映前の本番では、RSS が 1.9 GB で、`Session scan persistence failed: database is locked` が 66 回出ていた。
- `b4f28d7` で外した。
- `a17700d` で入れ直した。ps と transcript の読み取りは取引の外に出し、追記ゼロなら取引を開かない。
- 止まった子が解消するかは、未確認である。

### T6 端末の持ち主を runner へ

- 実装と実機検証が済んでいる。
- 枝は `agent/agent-graph-037-t6/integration` で、origin に push 済みである。main には入っていない。
- PR は権限の判定で作れず、利用者の操作待ちである。
- 検証は 3 つある。
  - api だけを再起動し、偽 claude の pid が同じまま生き、同じ terminalId に再接続して送信できた。main の版では端末が切れる。
  - `run.mjs` は全項目 PASS だった。
  - prod-gate は PASS だった。
- runner の再起動では、端末は今も切れる。範囲外である。
- 素のシェルも範囲外である。
- 出し方は、runner を先に出し、確認してから api を出す。

## 学んだこと

- 関門の locked 検知は、stderr の文字列を数えるだけである。握りつぶされた例外は捕まえない。
- 送信の合否と画面の更新を見ること。
- 本番へ反映するたびに、反映の前後で prod-gate の送信を流す。
- 試験が通っても、本番の経路は覆わない。T7-4 は HTTP 経路の試験だけで、outbox 経路の穴を見逃した。
- 閉じたグラフは再開できない。`agr launch` を終わったグラフに再実行すると、前回を退避して全タスクをやり直す。
- 終わったグラフへの追加は、別の識別子の新しいグラフにする。PR ノードの基点は、push 済みの枝にする。
- 本番は main の作業ツリーから動く。反映の前に編集を始めない。
- restart-check は、T6 が main に入るまで main では落ちる。

## 委譲の進め方

- 実装は Codex に任せる。ただし、Codex の環境は socket の listen と ps を拒否する。
- socket の試験、e2e、本番の写しの確認は、Claude の子に流させる。
- レビューは、実装と別の系統に任せる。
- 確かめの会話は、利用者のプロジェクトの外で起こす。利用者のプロジェクトで起こすと、サイドバーが試しの会話で埋まる。
- 起動し直しを頼むのは、変えたパッケージだけにする。runner を変えていないのに、runner の起動し直しを頼まない。

# 設定の画面と会話の入力欄と右のパネルの設計

## 目的

この文書は、設定の画面、会話の入力欄の下の選択欄、右のパネルの行を作り直す正本である。
実装者はこの文書だけを見て作る。見た目のために設定の意味は変えない。
色と文字と余白の値は `design-system.md` のトークンを使う。足りない値はこの文書の第 7 節で足す。

対象のファイルは次のとおりである。

| 画面 | ファイル |
| --- | --- |
| 設定の骨組み | `packages/dashboard/app/src/App.tsx` の `/settings` の分岐 |
| モデルの割り当て | `packages/dashboard/app/src/pages/settings/ModelAssignments.tsx`、`SettingsPage.tsx`、`settings.css` |
| 選び方のルール | `packages/dashboard/app/src/components/settings/SettingsFields.tsx`、`PerformanceWeights.tsx` |
| SSH | `packages/dashboard/app/src/components/SshSettings.tsx` |
| キーボード | `packages/dashboard/app/src/components/command/Commands.tsx`、`lib/keys.ts` |
| 入力欄 | `packages/dashboard/app/src/pages/conversation/ConversationPage.tsx`、`conversation.css`、`components/conversation/text.ts` |
| 右のパネル | `packages/dashboard/app/src/pages/graph/GraphOutline.tsx`、`graph.css` |
| 文言 | `packages/dashboard/app/src/lib/i18n.ts`、`docs/agents/ja-glossary.md` |

## 現状の診断

2026-10-11 に本番の日本語の画面を撮って確かめた。画像は `scratchpad/ja/` の 20 枚である。

| 問題 | 根拠 |
| --- | --- |
| 動くモデルが読めない | 割り当ての表の 24 セルのうち 14 セルが「標準モデルを使用」で、モデル名がない。コードでは `bands[weight] ?? bands.standard` で、ふつうの作業と同じ候補を使う。 |
| デフォルトが 2 つの意味を持つ | 表の「Opus 5.5 · デフォルト」は思考量が未指定の意味である。入力欄の「デフォルト ▾」はモデルの選択肢で、Claude の一覧の先頭の項目である。 |
| 予備が予備に見えない | 「上限時やエラー時: Opus 5.5」は 2 番目以降の候補である。`decide()` は利用枠と制約で 1 番目が外れたときに次を使う。エラー時の切り替えはコードにない。 |
| 保存が 2 つある | 「割り当てを保存」は `policy.toml` に書く。「設定ファイルに反映」は `~/.claude/settings.json` と `~/.codex/config.toml` と各役割のエージェントの定義に書き出す。画面にはこの違いの説明がない。 |
| 保存の順序が隠れている | 保存はプレビューを押すまで押せない。書き出しは保存するまで押せない。どちらも理由を示さない。 |
| 数字の意味が分からない | 「後回しにする使用率 70%」「候補から外す使用率 90%」「実績で選ぶ最低件数 20 件」は、主語と動作が欄の外にある。 |
| 文言が直訳である | 「進行役とは別の実装担当」「次の自分の番へ」「異なるモデル系統のレビュアー」は、何が起きるかを言っていない。 |
| 部品がブラウザ標準である | テーマと言語と制約と通知の種類は `select` である。枠付きのボタンが縦に並び、強弱がない。 |
| 一覧が長い | モデルを選ぶ窓は Claude の 12 件と Codex の全件を縦に並べる。Opus 4.6 や Sonnet 4.6 のような古い版も同じ重さで並ぶ。 |
| 節に強弱がない | 表示、割り当て、利用枠、実績、重視すること、制約、SSH、キーボードが同じ見出しで続く。キーボードは 28 行で画面の半分を占める。 |
| 右のパネルで切れる | `.graph-row-who` は幅の 20% が上限で、420px の区画では 84px である。「メインエー…」「コードレビ…」「antig…」になる。 |
| 設定の一部が届かない | `/settings` は `SettingsPage` を `policyOnly` で呼ぶ。エージェント、通知、保存、状態の節は画面に出ない。要確認。 |

## 1 方針

目指す印象は「静か」「密」「迷わない」の 3 つである。
手本は Linear、Raycast、Vercel の設定の画面である。

- 静か。色は操作とフォーカスだけに使う。面は地と浮いた面の 2 種類にする。線は `--line` の 1px だけにする
- 密。1 行の高さは 32px か 40px に揃え、値は右端に揃える。説明は 1 行の `--type-meta` にし、長い説明を置かない
- 迷わない。いま何のモデルが動くかを必ず名前で出す。主ボタンは画面に 1 つだけにする。めったに触らないものは畳む

言葉の決まりは次のとおりである。

- 「デフォルト」を画面から消す。モデルは名前で出し、思考量の未指定は「自動」と書く
- 「標準」を使わない。ふつうの作業の列と同じ候補を使うセルは「ふつうと同じ」と書く
- 設定の名前は「何がどうなるか」の文にする。数値は文の中に置く
- 保存は「保存」だけにする。外部のファイルを書く操作は「書き出す」と呼ぶ

## 2 情報の組み立て

### 節の並び

`/settings` の 1 頁に 5 つの節を置く。上から順に、よく触るものにする。

| 順 | 節 | 日本語 | 英語 | 既定の状態 |
| --- | --- | --- | --- | --- |
| 1 | models | モデル | Models | 開く |
| 2 | rules | 選び方のルール | Selection rules | 畳む。要約の 1 行を出す |
| 3 | appearance | 表示 | Appearance | 開く |
| 4 | ssh | SSH の接続先 | SSH connections | 接続先が 0 件なら畳む |
| 5 | keys | キーボードショートカット | Keyboard shortcuts | 畳む。件数だけ出す |

見出しの下に節への移動の帯を置く。帯は `position: sticky` で上端に貼り付く。
帯の中は 5 つの ghost のボタンで、押すと節の先頭へ滑らかに移動する。

```
+--------------------------------------------------------------+
| ← 戻る                                                   設定 |
+--------------------------------------------------------------+
| モデル   選び方のルール   表示   SSH の接続先   キーボード        |  sticky
+--------------------------------------------------------------+
| モデル                                                        |
|   説明の 1 行                                                 |
|   [表]                                                        |
|   おすすめの組み合わせ  性能重視 | バランス | 節約                |
|                                             [書き出す] [保存] |
|                                                              |
| ▸ 選び方のルール   利用枠 70/90% · 実績 20 件 · 制約 2 件        |
|                                                              |
| 表示                                                         |
|   テーマ                         OS に合わせる | ライト | ダーク |
|   言語                                       日本語 | English |
|                                                              |
| ▸ SSH の接続先   0 件                                          |
| ▸ キーボードショートカット   28 件                               |
+--------------------------------------------------------------+
```

### 節ごとに見せるものと隠すもの

| 節 | 見せる | 隠す |
| --- | --- | --- |
| モデル | 役割と作業の重さの表。おすすめの組み合わせ。保存と書き出し。 | 重さの基準の文。その他のモデルの手入力。 |
| 選び方のルール | 要約の 1 行。開くと、やりとりの上限、利用枠、実績、制約。 | なし。 |
| 表示 | テーマと言語。 | 密度、差分の並び、時刻の形式は `APPEARANCE_CHOICES` にあるが `/settings` に出ていない。要確認のうえ、出すならここに置く。 |
| SSH の接続先 | 接続先の一覧。追加と保存。 | 接続テストの結果は行の中に 1 行で出す。 |
| キーボード | 28 件の操作と割り当て。 | 群に分ける。移動、会話、承認、画面の 4 群にする。 |

### 保存の流れ

保存は節ごとに 1 つの主ボタンにする。頁の下の共通の保存は置かない。

| 節 | ボタン | 動き |
| --- | --- | --- |
| モデル | 保存 | `settings.previewPolicy` を呼び、変更前後の表を浮いた面で出す。面の中の「この内容で保存」で `settings.write` を呼ぶ。 |
| モデル | 書き出す | `settings.previewProvider` を 3 つの提供元で呼び、差分を浮いた面で出す。面の中の「書き出す」で `settings.applyProvider` を呼ぶ。 |
| 選び方のルール | 保存 | モデルの節と同じ `policy` の保存である。どちらの節で押しても同じ流れにする。 |
| 表示 | なし | 変更は即時に `localStorage` に入る。 |
| SSH の接続先 | 保存 | `ssh.write` を呼ぶ。 |
| キーボード | 保存 | `settings.write` の `config.keys` を呼ぶ。 |

未保存の変更がある節は、見出しの右に「未保存」を `--state-approval` の点と語で出す。
「書き出す」は未保存のときは押せない。押せない理由を `title` に「先に保存する」と入れる。

## 3 モデルの割り当て

### 表の形

```
役割                軽い作業              ふつうの作業            重い作業
------------------------------------------------------------------------------
メインエージェント    Opus 5.5             [◉ Opus 5.5        ]   Opus 5.5
                    ふつうと同じ                                  ふつうと同じ
------------------------------------------------------------------------------
実装          ✎     [◎ GPT-6.1-Sol low ]  [◎ GPT-6-Astra high]  [◎ GPT-6-Astra xhigh]
                    予備 Opus 5.5          予備 Opus 5.5           予備 Opus 5.5
------------------------------------------------------------------------------
校正                Gemini 3.8 Flash      [◆ Gemini 3.8 Flash]   Gemini 3.8 Flash
                    ふつうと同じ                                  ふつうと同じ
```

- 行の高さは 52px にする。1 行目にモデル、2 行目に補足を置く。補足がない行も高さを変えない
- 列の幅は、役割が 20%、3 つの作業が 26.6% ずつにする
- 行の区切りは `--border` の横線だけにする。縦線は引かない
- 役割の名前は `--type-ui` の `--fg-1` にする。基準がある役割には右に 16px の鉛筆の印を `--fg-3` で置く

### セルの 2 つの状態

| 状態 | 条件 | 1 行目 | 2 行目 |
| --- | --- | --- | --- |
| 個別に決めた | `bands[weight]` が定義されている | 枠付きのチップ。提供元の印、モデル名、思考量。 | 2 番目以降の候補があれば「予備 名前 → 名前」。 |
| ふつうと同じ | `weight !== 'standard'` かつ `bands[weight] === undefined` | 枠なし。モデル名を `--fg-3` で書く。印は置かない。 | 「ふつうと同じ」を `--type-meta` の `--fg-3` で書く。 |

ふつうと同じセルでも、ふつうの作業の 1 番目の候補の名前を必ず書く。名前のないセルを作らない。
ふつうの作業の列は常に個別に決めた状態である。この列には「ふつうと同じ」は出ない。

### チップ

- 高さ 32px、枠 `--border`、角 `--radius-1`、地 `--bg-0`、内側の左右 `--space-2`
- 中は左から、提供元の印 16px、モデル名 `--type-ui` の `--fg-1`、思考量、右端に 12px の下向きの印
- 思考量は `--type-mono` の `--fg-3` で、`low` や `xhigh` の値をそのまま書く。未指定なら何も書かない
- 指を置いたら地を `--bg-2` にする。開いているときは枠を `--accent` にする
- モデル名は `text-overflow: ellipsis` で切る。切れたときは `title` に全名を入れる

### 思考量の見せ方

- 思考量は提供元の設定の値であり、`low`、`medium`、`high`、`xhigh`、`max` などの英語の語をそのまま使う
- 日本語でも翻訳しない。`model_reasoning_effort` に書かれる値と画面の語を一致させるためである
- 未指定は表では空白、選ぶ窓と入力欄では「自動」と書く。英語は `Auto` とする
- Antigravity には思考量がない。選ぶ窓に思考量の段を出さない

### 予備のモデルの見せ方

- 2 番目以降の候補を「予備」と呼ぶ。英語は `Backup` とする
- 2 行目に「予備 Opus 5.5」と書く。3 つ以上なら「予備 Opus 5.5 → Sonnet 5.5」と矢印でつなぐ
- 2 行目に `title` で「利用枠の上限や制約で最初のモデルが使えないとき、順に使う」を入れる
- 「エラー時」という語は使わない。コードにその動きがないためである

### モデルを選ぶ窓

チップを押すと、チップの直下に幅 440px の浮いた面を出す。画面の右端に収まらなければ左に寄せる。

```
+------------------------------------------------+
| 実装 · 重い作業                               × |
+------------------------------------------------+
| 使うモデル                                       |
|  ⠿ ◎ GPT-6-Astra        思考量 自動 low … xhigh |
| 予備 1                                           |
|  ⠿ ◉ Opus 5.5           思考量 自動 low … max   |
|  + 予備を追加                                    |
+------------------------------------------------+
| 🔍 モデルを探す                                   |
| Claude                                      ↻  |
|   ◉ Opus 5.5                                    |
|   ◉ Fable 5.1                                   |
|   ◉ Sonnet 5.5                                  |
|   ◉ Haiku 4.5                                   |
|   古いバージョン 8 件 ▸                           |
| Codex                                       ↻  |
|   ◎ GPT-6.1-Sol                                 |
|   ◎ GPT-6-Astra                                  |
|   古いバージョン 3 件 ▸                           |
| Antigravity                                 ↻  |
|   ◆ Gemini 3.8 Flash                              |
| ▸ 名前を直接入力                                  |
+------------------------------------------------+
| ふつうと同じにする                                 |
+------------------------------------------------+
```

- 上の段は候補の列である。1 番目に「使うモデル」、2 番目以降に「予備 1」「予備 2」の見出しを付ける
- 候補の行は 40px にする。左に 16px のつまみ、提供元の印、名前、右に思考量の区切りボタンを置く
- 思考量の区切りボタンは高さ 24px、`--type-meta`、選んだ値は地 `--bg-3` と語 `--fg-1` にする
- 候補の行に指を置くと、右端に「削除」の ghost のボタンが出る。上下の矢印はつまみのドラッグに置き換える
- 選んでいる候補の行は地を `--bg-2` にする。下の一覧で押したモデルはこの候補に入る
- 下の段は提供元ごとの一覧である。先頭に検索の入力を置く。入力すると名前の部分一致で絞る
- 一覧の行は 32px、提供元の印、名前を出す
- いまの候補と同じモデルは地 `--bg-3` にする
- 「ふつうと同じにする」は `weight !== 'standard'` のときだけ、面の下に ghost で置く
- 「名前を直接入力」は畳んだ段にする。中は提供元の区切りボタン、名前の入力、ランクの区切りボタンにする

### 古い版を隠す規則

- 表示名を `^(.*?)[ -]?(\d+(?:\.\d+)?)(?:[ -](.+))?$` で分け、前の語と後ろの語を系統の鍵にする
- 例は次のとおりである。`Opus 5.5` は `Opus`、`GPT-6.1-Sol` は `GPT/Sol`、`Gemini 3.8 Flash` は `Gemini/Flash` になる
- 鍵ごとに版の数が最大の 1 件だけを出す。残りは「古いバージョン N 件」の畳みに入れる
- 数のない名前は常に出す。`GPT-Reserve` や `Default` がこれに当たる
- 表のどこかのセルで使っているモデルは、版が古くても常に出す
- 畳みを開いた状態は窓を閉じるまで保つ。保存はしない

### おすすめの組み合わせ

- 表の下に「おすすめの組み合わせ」の見出しと 3 つの区切りボタンを置く
- 押すと、変更前後の表を浮いた面で出す。いまの `assignment-preset` の役割を引き継ぐ
- 面の下に「表に反映」の primary と「やめる」の ghost を置く
- 反映は表を変えるだけである。保存は節の「保存」で行う。面の末尾にその 1 行を `--type-meta` で書く

### 重さの基準

- 役割の鉛筆の印を押すと、その行の下に 1 行を開き、3 つの入力を横に並べる
- 入力は 1 行の `textarea` で、高さは 60px にする。列の幅は表の列に揃える
- 「閉じる」の ghost を右端に置く

## 4 会話の入力欄の下の選択欄

### 形

```
+------------------------------------------------------------------+
| メッセージを入力…                                                   |
|                                                                  |
+------------------------------------------------------------------+
| ◉ Opus 5.5 ▾   思考量 high ▾                       [□ 中断] [↑ 送信] |
+------------------------------------------------------------------+
```

- 左に 2 つの ghost の小さいボタンを置く。モデルと思考量である。`select` は使わない
- 思考量のボタンは Codex のときだけ出す。Claude のときは出さない。要確認。Claude で思考量を渡す経路があれば出す
- 提供元の選択は会話を始める前だけに出す。区切りボタンで「Claude | Codex」にする
- 「適用」のボタンは消す。メニューの中の「適用」に置き換える

### 動くモデルの名前

何も選んでいないときも、必ず実際に動くモデルの名前を出す。名前は次の順で決める。

| 順 | 根拠 | 使うとき |
| --- | --- | --- |
| 1 | 実行中の `run.model` | 会話が動いている |
| 2 | 利用者が選んだ値 | 一覧から選び、まだ適用していない |
| 3 | `policy.roles.orchestrate.standard` の、同じ提供元の 1 番目の候補 | 会話がまだない |
| 4 | `config.agents[provider].model` | 3 がない |

- 一覧の先頭の「Default (recommended)」を選んだときは、3 の名前を出し、右に「おすすめ」を `--type-meta` で添える
- 3 と 4 の名前が、提供元の設定ファイルの実際の値と違う可能性がある。要確認。違うなら `settings.status` に実際の値を足す

### モデルのメニュー

- ボタンの直上に幅 320px の浮いた面を出す
- 先頭に「おすすめ · Opus 5.5」の行を置く。これは一覧の `Default` の項目である
- 続けて提供元の一覧を出す。古い版を隠す規則は第 3 節と同じにする
- 選んだ行は地 `--bg-3` にする。いま動いている行には右に「使用中」を書く
- 面の下に「適用」の primary の小さいボタンを置く。選び直していないときは押せない
- Codex で返答の途中なら、面の中に「返答が終わると変更できる」を `--type-meta` で書き、行を押せなくする

### 思考量のメニュー

- 幅 200px の浮いた面に「自動」と `CODEX_EFFORTS` の値を縦に並べる
- 「自動」を選ぶと `effort` を空にする。ボタンには「思考量 自動」と書く
- 値は `--type-mono` でそのまま書く。翻訳しない

## 5 右のパネルの行

### 行の形

区画の幅が 560px 未満のとき、行を 2 行にする。グラフの頁の木の欄も 400px なので同じ形になる。

```
● ⚙ 本番の日本語の画面を撮る                         1m
      実装 · Claude Opus 5.5 · 作業中
● ✓ 根の系列の直しをレビューする                   23:28
      コードレビュー · Codex · 推定
○ ☰ agent-graph-027                                   
      アドバイザー · 以前 24
```

- 行の高さは 48px にする。実行中の行は 2 行目に「いまの作業」を足して 68px にする
- 1 行目は左から、状態の点、役割の印、名前、右端に時刻か経過を置く。名前は `--type-ui` の `--fg-1` で 1 行に切る
- 2 行目は `--type-meta` の `--fg-3` で、役割、モデル、補足を「·」でつなぐ。名前の左端に揃える
- 2 行目は `min-width: 0` で切り、`title` に全文を入れる。1 行目の名前より先に 2 行目を切らない
- 根の行の 2 行目は「メインエージェント · Opus 5.5 · サブエージェント 24」にする。モデルは `agentName()` で取る
- 「推定」と「×2」のような補足は 2 行目の末尾に置く。1 行目に置かない
- 失敗と、あなたの番の語は 1 行目の右端に状態の色で出す。時刻は出さない

### 幅が 560px 以上のとき

- いまの 1 行 32px のままにする
- `.graph-row-who` の `max-width: 20%` を `max-width: 240px; min-width: 120px` に変える
- `.graph-row-title` は `min-width: 160px` にする。名前を先に切り、役割とモデルを残す

- 各項目は高さ 24px、左右の内側 `--space-3`、`--type-ui` の `--fg-2`、角 `--radius-1` から 2px 引いた 4px
- 選んだ項目は地 `--bg-0`、語 `--fg-1`、影 `0 1px 2px rgb(15 17 26 / 0.08)`。暗い表示の影は `rgb(0 0 0 / 0.4)`
- 使えない項目は語を `--fg-4` にする

メニューのボタンの形は次のとおりである。

- ghost のボタンに右端の 12px の下向きの印を足す
- 開いている間は地を `--bg-2` にする
- 面は `--bg-0`、`--border`、`--radius-2`、`--shadow`。内側は `--space-1`
- 行は 32px、`--radius-1`、指を置いたら `--bg-2`、選んだ行は `--bg-3`
- 矢印の上下で移動し、Enter で選び、Escape で閉じる。開いたら選んでいる行にフォーカスを置く

### ボタンの種類と強弱

| 種類 | 使う所 |
| --- | --- |
| primary | 節の「保存」と、浮いた面の確定。1 つの面に 1 つだけ。 |
| secondary | 「書き出す」「追加」「接続を試す」「表に反映」。 |
| ghost | 「やめる」「削除」「閉じる」、節の移動の帯、入力欄のモデルと思考量。 |

- 設定の頁のボタンは高さ 32px、`--type-ui`、左右の内側 `--space-3`
- 入力欄の下と浮いた面の中は 28px にする
- 節の操作の行は右寄せにする。primary を右端、secondary をその左、ghost をさらに左に置く
- ボタンの間は `--space-2` にする

### 行と入力

- 設定の行は高さ 40px、左に名前、右に値。名前は `--type-ui` の `--fg-1`、値は右端に揃える
- 行の間は `--border` の横線だけにする。カードの外枠は引かない
- 文の中の数値の入力は幅 64px、高さ 28px、`--type-ui`、右揃え。文は `--fg-1`、入力の枠は `--border`
- 入力の枠は `--line` にする。`--input-line` の濃い枠はやめ、フォーカスで `--accent` にする
- 実績の重みのつまみは次の「実績の重み」の決まりに従う

### 実績の重み

4 つの項目に色を付けない。4 本のつまみは同じ見た目にする。
色は値を動かしているつまみだけに付ける。理由は、項目の色は意味を持たず、強弱を壊すだけだからである。
下の 4 色の帯は消す。4 本の軌道が同じ幅で並ぶので、塗りの長さだけで割合を比べられる。
項目の左の色の点も消す。

```
実績の重み
合格率              ━━━━━━━━━━━━━━●──────────────────────   [ 40] %
レビューの承認率      ━━━━━━━━━━●──────────────────────────   [ 30] %
やりとりの少なさ      ━━━━━●───────────────────────────────   [ 20] %
トークンの少なさ      ━━●──────────────────────────────────   [ 10] %
```

| 部分 | 値 |
| --- | --- |
| 行 | 高さ 40px。左に名前、真ん中に軌道、右に数値の入力と `%`。行の間は `--border` の横線だけにする。 |
| 名前 | 幅 200px、`--type-ui` の `--fg-1`。色の点は置かない。 |
| 軌道 | 高さ 4px、角 2px、色 `--slider-track`。幅は行の残り全部にする。 |
| 塗り | 軌道の左から値の分だけ塗る。色は `--slider-fill`。 |
| 取っ手 | 直径 12px の円。地 `--bg-0`、枠 1px の `--slider-fill`。 |
| 動かしている間 | 指を置いた、フォーカスした、ドラッグ中のつまみだけ、塗りと取っ手の枠を `--accent` にする。 |
| フォーカス | 取っ手に `outline: 2px solid var(--focus)` と `outline-offset: 1px`。 |
| 数値 | 幅 64px、高さ 28px、右揃え、`--type-ui`。枠は `--line`。 |
| 変化 | 塗りの幅は `transition` を付けない。色だけ `--duration` で変える。 |

- `input[type=range]` の見た目は `appearance: none` で消し、軌道と塗りと取っ手を自前で描く。`accent-color` は使わない
- 1 つを動かすと残りが比例で変わる動きはいまのままにする。`PerformanceWeights.tsx` の `allocatePercent` は触らない
- `aria-valuetext` に「40%」を入れる。見た目の変更で読み上げを減らさない
- 4 つの合計が 100 であることは数値の列で分かる。合計の表示は足さない

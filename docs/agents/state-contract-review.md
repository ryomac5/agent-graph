### 1. 送信元を識別できない証拠で受領を確定している

**確かめたこと。** SC:347 は `<bash-input>`、`<command-name>`、`queued_command` を「送信の印」として `received confirmed` にする。しかし E2 の `C/1c0d055c-8912-452b-b273-47e9874df7e8.jsonl:137`、`:145` は入力の種類を表す `<bash-input>` であり、本製品の `cmd_id` を含まない。seq 301136、301145 の本文を正規化すると各 watch の本文と一致するが、それだけでは送信元を証明しない。

**推測／影響。** 元の送信が失われた世界と、届いた世界が同じ観測になる。本文・時刻の照合を増やしても区別できず、誤った Delivered が残る。E2 は「未着と断定できない」実例であり、「本製品の送信を confirmed にできる」実例ではない。

**直し方。** 受領確定は、送信操作と受信記録を結ぶ相関証拠に限る。本文と時刻の一致は候補として confidence・照合範囲・根拠を保存し、確定受領と区別する。普通の入力、`!`、スラッシュコマンド、キューを同じ原則で扱う。既存 `closed` の一律 `received` 移行（SC:136）も旧照合の確度を引き継ぐ必要がある。SC:346 の SDK/app-server 経路も ID の往復と永続対応を明記すること。現行 `packages/runner/src/hosts/claude/index.ts:158` と `packages/runner/src/hosts/codex/index.ts:164` の `send` は戻り値が void で、契約の一文だけでは対応の保存を保証しない。

**直し方。** プロセス・ホストの生存と、run/session/thread の論理的な閉鎖を分ける。物理的終了はそのプロセスの exit、または OS 上の PID と開始指紋を照合した消失だけにする。`procStart` は登録 JSON 同士でなく OS の現在値と比較する。登録の不在、開いたファイルの不在、archived、別名への置換は、それぞれ観測範囲・論理状態の証拠に限定する。物理終了後の同一プロセス世代の復活は許さず、論理再開の規則と混ぜない。

### 8. 報告・最終応答・検証合格を、同じ「成功」にしている

| 同一性・順序 | E3 の hook/transcript と親子記録を遅延・重複・再読を含めて並べ替える。旧 turn の Stop を新 turn 開始後に届ける。 | run 数だけでなく ID、所属、所有プロセス、各軸、入力対象と根拠が一致する。旧 turn の完了で新 turn を閉じない。 |
| 解釈・競合 | E4 のフラグ訂正、E5 相当の識別可能な競合、再解釈の途中停止と再起動。競合の後に正常走査する。 | 新旧版を混ぜない。走査成功だけで未解決競合を消さない。訂正と有効化を追跡できる。 |
| snapshot | 台帳追記なしの期限切れ、配達だけの変更、同一性の訂正、API 再起動、UI 切断。 | 必要な版が進む。終了・成功の歴史を失わない。各応答内が一貫し、切断画面が現在の状態だと誤認させない。 |
| 表示・公開 | 有効な全状態の組、対象外の結果、成功した旧試行と実行中の新試行、未吸収キュー。 | 表示が一意で、Done と Working の選択を層ごとに補完しない。必須の PTY 移行試験が未実行なら合格にしない。 |

## バイナリ証拠の再現性

バイナリの行番号はファイル先頭から LF を数えた 1 始まり、byte は 0 始まり。最小化されたコードのため、行番号だけでなく byte と検索語も併記した。実行はしていない。調査時の `claude` の実体は B300、稼働登録 S に記された版は B299 だったため、両方を区別した。

| 実体 | SHA-256 |
| --- | --- |
| B299 | `ba5ab7b8c195fa03ab8d5bf3915c76153b576a2c40e79a5c46e265e7ed9744b3` |
| B300 | `475517caa611e3318a2f298fa071287ec98955538df78c58f709ecc01e5ae2d3` |

対象定義書の調査開始時 SHA-256 は `b1fcf564be54bfd41b4ab0aca9aef40db9e2158f73a343160944c6020081b053`。本書の指摘はこの版に対するものであり、定義書自体の修正は行っていない。

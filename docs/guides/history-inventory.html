分類の鍵と診断

鍵は provider・行の type・副種別の欄・副種別の値の組。Claude は attachment.type、system.subtype、queue-operation.operation、message.content.type を抽出する。queued_command は attachment.queued_command.commandMode+origin.kind と、commandMode・origin.kind の JSON 配列を鍵にする。欠落値は <missing> とする。

Codex は payload.type、payload の種類ごとの content.type、通知の params.item.type を抽出する。event_msg の item_started / item_completed は、それぞれ payload.item_started.item.type / payload.item_completed.item.type を鍵にする。response_item の function_call は、spawn_agent・send_message・wait_agent の場合に payload.function_call.name を使い、他の道具は従来の function_call として分類する。旧形式メタは legacy_meta に分ける。

件数は鍵を含む行数。同じ種類のブロックが同じ行に複数あっても一件。最初のファイルは走査内の番号と行番号で示し、実パスは出さない。未分類があれば、種別の形だけを残した見本を出して終了コード 1 にする。本文・パス・識別子は伏せる。読めないディレクトリや途中の走査失敗も終了コード 1 にする。

不正 JSON・JSON オブジェクト以外・type がなく他の分類鍵もない行は、種類の棚卸しに含めない。読み手は従来の診断だけを残し、Unclassified history kinds を重ねない。未知の種類には未分類診断を残し、従来の診断の source_event_id と payload は変えない。

# S17: 委譲の実行中の api 再起動

runner が受理・起動を保持し、api を止めた間に確定発言と実行終了と委譲完了を台帳へ追記する。
本文は伏せた値で、ホストと受付の事実構造を再現した決定的な標本である（実機の履歴から採取したものではない）。
`input.json` の先頭 4 件の後に api を停止し、残りを追記する。
`expected-ledger.json` は欠落と重複と起動回数、`expected-projection.json` は最終状態の期待である。
試験は再送・逆順・再構築も検証する。delta は耐久の事実ではないため復元の期待に含めない。
再構築の一致は、台帳から作る全投影テーブルの全欄で確かめる。
配信に重ねる現在の decision、走査の証拠、評価時刻は台帳だけでは再現できず、一致条件に含めない。
socket の有無にかかわらず、別の走査で現在状態が変わっても永続投影が一致することを確かめる。
同じ走査結果の decision_id は照会時刻が変わっても一致し、生存・pid・procStart や期限切れが変われば区別する。

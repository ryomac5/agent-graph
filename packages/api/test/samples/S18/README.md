# S18: CLI による状態変化の通知

`input.json` の受理から終わりまでの事実を、一時台帳へ追記する。
`watch.test.ts` が別プロセスで API CLI を起動し、開始時の受理の行を
確認した後に残りを流す。`expected.json` が行の状態の順と終了コードを定める。
失敗、中断、拒否も同じ経路を使う。

開始時点ですでに終了した場合、1 行だけ出して終了することも各標本で確かめる。
追加のテストはページ境界、無関係の追記、判断待ち、writer の再起動、グラフの
複数タスク、会話の終了の根拠、対象不明と読み取り失敗を確かめる。
グラフの所属は core の `planner:[graphId,taskId,attempt]` という requestId で照合する。
MCP の受理と `wait` の進捗通知は、この API CLI の標本の検証範囲に含めない。
